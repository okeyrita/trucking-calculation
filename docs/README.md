# Архитектура и технический стек остальных частей проекта

Эта папка — не код и не задачи на реализацию. Это разбор того, **как решать** оставшиеся
части ТЗ: какой стек брать, какие есть пути, где риски и какие решения нужно принять до
того, как будет написана первая строка.

Реализован пока один модуль — маршрутизация и контроль топлива (см. корневой
[README.md](../README.md)). Всё остальное описано здесь.

## Как пользоваться

В каждом документе есть раздел **«Решения, которые нужно принять»** — это вопросы к
заказчику или к вам, без ответов на которые писать код преждевременно. Начинать стоит
именно с них: в этом проекте сроки определяются не скоростью разработки, а тем, как
быстро появляются доступы к чужим системам.

Оценки трудозатрат везде даны в человеко-неделях для одного разработчика и **не включают**
ожидание доступов, согласований и ответов вендоров. На практике это ожидание и есть
критический путь.
